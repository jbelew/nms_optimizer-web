# GA4, Measurement Protocol, and BigQuery Telemetry Contract

## Context

`nms_optimizer-web` dispatches analytics events through two transports: direct client-side `window.gtag` (`gtag.js` injected by [`tracking.ts`](../../src/utils/analytics/tracking.ts) without the legacy `react-ga4` wrapper) when unblocked, and a server-side Measurement Protocol relay (`/api/events` in `nms_optimizer-service`) when ad blockers or DNS sinkholes block Google Analytics scripts. Downstream, two public Routed Dialogs—[`UserStatsDialog`](../../src/components/AppDialog/UserStats/UserStatsDialog.tsx) (`/userstats/`, backed by `/analytics/popular_data`) and [`PerformanceDialog`](../../src/components/AppDialog/Performance/PerformanceDialog.tsx) (`/performance/`, backed by `/analytics/performance_data`)—query the GA4 BigQuery Export dataset (`events_*` and `events_intraday_*`) as their primary data source, with the GA4 Data API (`BetaAnalyticsDataClient`) as a fallback.

Several subtle cross-system invariants govern how GA4, Measurement Protocol, and BigQuery serialize and aggregate event parameters:

1. **Boolean Parameter Serialization Divergence**: Client-side `gtag` serializes boolean parameters (`true` / `false`) as URL query strings, which BigQuery stores in `event_params.value.string_value` (`"true"` / `"false"`). In contrast, the GA4 Measurement Protocol JSON API converts JSON booleans (`true` / `false`) into `event_params.value.int_value` (`1` / `0`), leaving `string_value` as `NULL`.
2. **Web Vitals Snapshot vs. Delta Aggregation, Bucketing, and Non-Production Traffic in BigQuery**: Starting in `v8.4.3`, [`tracking.ts`](../../src/utils/analytics/tracking.ts) (`sendVitalsMetric()`) emits full cumulative `metric.value` snapshots for `INP` on every `visibilitychange` update (preventing negative deltas when lower-percentile updates fire) and single-fire latencies for `TTFB`, `FCP`, and `LCP`, while emitting incremental `metric.delta * 1000` values for `CLS` (and legacy pre-`v8.4.3` `INP`), all keyed by `label: metric.id` (`^v\d+-\d+-\d+$`). Summing `value` indiscriminately across all Web Vitals inflates multi-report `INP` sessions and retried single-fire beacons, overwriting `label` with a DOM selector breaks per-instance grouping, and selecting `ANY_VALUE(event_timestamp)` without partitioning by `metric_name` makes hourly bucketing non-deterministic for long-lived tabs. Additionally, local development (`localhost`, `127.0.0.1`) and preview deployments (`*.pages.dev`, `*.herokuapp.com`) share the GA4 property, while server-relayed Measurement Protocol events (`/api/events`) arrive in BigQuery with `device.web_info.hostname` unset (`NULL`/empty).
3. **GA4 Built-in `appVersion` Limitation vs. Custom Definitions & BigQuery Export**: GA4's built-in `appVersion` dimension is populated only for native mobile app streams (iOS/Android Firebase SDKs), not web data streams. Web release tracking therefore requires dual user-scoped (`app_version`) and event-scoped (`app_version`) custom definitions sent across both `gtag` and `/api/events`. Meanwhile, BigQuery Export captures every key in `event_params` automatically without console registration, whereas the GA4 UI and `BetaAnalyticsDataClient` require explicit Custom Dimension / Custom Metric registration (subject to GA4 property limits) or standard recommended parameters (`content_type` -> **Content type**, `item_id` -> **Content ID**).
4. **Measurement Protocol Session, Engagement, and Device/Geo Attribution Gaps**: GA4's Measurement Protocol (`/mp/collect`) reserves `session_start` and `first_visit` (rejecting manual submission), and leaves ad-blocked sessions unattributed (`Unassigned` session, `0` active users, missing device/country) unless standard events carry an integer `session_id`, a positive integer `engagement_time_msec`, `user_properties`, page context (`page_location`, `page_path`, `page_title`), `User-Agent`, and client IP (`ip_override`).
5. **Fixed-Supercharged Recommended Builds vs. Organic Solver Telemetry**: Platform Types with fixed supercharged slot layouts (`superchargedFixed: true`, such as Exosuit and Exocraft) provide static curated **Recommended Builds**, so charting their supercharged technology popularity in `/userstats/` reflects preset layouts rather than organic solver variance.
6. **Cross-Origin Referrer Policy, Server-Relayed Attribution, and URL Query Sanitization**: Modern browsers default to `Referrer-Policy: strict-origin-when-cross-origin`, truncating external `document.referrer` values to origin-only (`https://www.reddit.com/`), while GA4's Measurement Protocol (`/api/events`) does not populate GA4's session-level `traffic_source` dimensions from `page_referrer` (leaving ad-blocked sessions marked as `(direct) / (none)` even though `event_params.page_referrer` in BigQuery preserves the true external origin). Furthermore, [`useUrlSync.tsx`](../../src/hooks/useUrlSync/useUrlSync.tsx) strips non-`platform`/`grid` query parameters and normalizes `/?platform=` on initial mount, which previously fired a duplicate `page_view` in [`Seo.tsx`](../../src/components/Seo/Seo.tsx) that overwrote the external `page_referrer` with a self-referrer and stripped inbound `utm_*` / `ref` parameters before async `gtag.js` initialization.

## Decision

1. **String-Normalized Boolean Event Parameters & Clean `value` Semantics**: All boolean flags in [`GA4Event`](../../src/types/analytics.ts) (such as `supercharged`, `forced`, `is_custom_grid`, `is_custom_modules`, and `fatal`) are normalized to `"true"` or `"false"` strings before dispatch in [`tracking.ts`](../../src/utils/analytics/tracking.ts) so client `gtag` and server `/api/events` write identical `string_value` columns in BigQuery and GA4 (while passive flags map `nonInteraction` to GA4's native `non_interaction` parameter). Non-monetary UI events omit placeholder `value: 1` fields so GA4 **Event value** totals stay clean; `value` is emitted only on `earn_virtual_currency` (`value: 1`) and `performance_metric` (`value: Math.round(rawValue)`, preserved alongside `metric_value` to back the existing `Performance Value` Custom Metric). On the read side, `/analytics/popular_data` coalesces `value.string_value` with `IF(value.int_value = 1, 'true', IF(value.int_value = 0, 'false', NULL))` to preserve historical server-relayed events.
2. **Web Vitals Attribution, Grid-Cell Selector Normalization, Snapshot vs. Delta BigQuery Aggregation, and Production Host Filtering**: [`tracking.ts`](../../src/utils/analytics/tracking.ts) initializes non-blockingly during boot, registers Core Web Vitals observers immediately, preserves `label: metric.id` (`^v\d+-\d+-\d+$`) for BigQuery instance grouping, collapses per-coordinate `#grid-cell-<row>-<col>` IDs into `#grid-cell` across `INP`, `LCP`, and `CLS` so grid interactions aggregate cleanly in `customEvent:interaction_target`, and omits the unused `TBT` observer. On the read side, `/analytics/performance_data`, `/analytics/popular_data`, and [`scripts/report-inp.py`](../../scripts/report-inp.py) (`bun run perf:inp`) filter BigQuery source rows to production client hostnames (`nms-optimizer.app`, `www.nms-optimizer.app`) and server-relayed Measurement Protocol events (where `device.web_info.hostname` is `NULL` or empty) whose `page_location` (when present) is not a loopback or preview origin (`localhost`, `127.0.0.1`, `*.pages.dev`, `*.herokuapp.com`), deduplicating daily and intraday shard overlap. In both `get_performance_analytics_data()` and `scripts/report-inp.py`, `event_value` coalesces `metric_value` and `value`, partitions explicitly by `(user_pseudo_id, metric_name, metric_instance_key)`, buckets each metric instance deterministically using `MAX(event_timestamp)`, sums incremental deltas (`SUM(event_value)`) for `CLS` and legacy pre-`v8.4.3` `INP`, and resolves `v8.4.3+` (and unversioned) `INP`, `TTFB`, `FCP`, and `LCP` instances to their latest chronological `event_value` (`ORDER BY event_timestamp DESC LIMIT 1`). While [`PerformanceDialog`](../../src/components/AppDialog/Performance/PerformanceDialog.tsx) (`/performance/`) charts all-visitor percentiles (`p50`/`p75`/`p90`), `scripts/report-inp.py` additionally surfaces a 28-day CrUX Readiness Banner (`Android + Chrome` mobile vs. `Desktop + Chrome` `p75` and `% > 200ms`) and `--device crux-mobile` filtering so CLI diagnostics match Google Search Console's CrUX cohorts rather than GA4 Data API arithmetic means.
3. **Server-Relay (`/api/events`) Session, User-Property, and Geo/UA Parity**: [`tracking.ts`](../../src/utils/analytics/tracking.ts) maintains a 30-minute rolling `session_id` and `session_number` (preferring the `_ga_<container>` cookie when available and falling back to `sessionStorage`), computes foreground `engagement_time_msec` deltas (`1..1800000` ms) on interactive events, and attaches `app_version`, `is_installed`, default page context (`page_location`, `page_path`, `page_title`), and `userProperties` (`app_version`, `is_installed`, `platform_type`) to both client `gtag` and `/api/events` payloads, flushing queued events on both `visibilitychange -> hidden` and `pagehide` (Safari navigation parity). In `nms_optimizer-service`, `/api/events` validates client events against `ALLOWED_CLIENT_EVENT_NAMES`, strips reserved `_*` parameters, forwards `user_properties`, `User-Agent`, and client IP (`ip_override` from `CF-Connecting-IP` / `X-Forwarded-For`), and dispatches Measurement Protocol requests on a fork-safe background daemon queue so `/api/events` never blocks Gunicorn workers.
4. **Dual-Scope `app_version`, Custom Definitions, and Built-In `select_content` Dimensions**: Web release tracking sets `app_version` as both a user property and an event parameter on every event. High-level reporting dimensions (`platform`, `tech`, `supercharged`, `solve_method`, `bonus_status`, `method`, `metric_name`, `interaction_target`, `interaction_type`, `load_state`, `app_version`, `tracking_source`, `is_installed`, `reason`, `reset_scope`, and user-scoped `platform_type`) and metrics (`value`, `solve_duration_ms`, `input_delay`, `processing_duration`, `presentation_delay`) are registered in GA4, all Key Events (`optimize_tech`, `apply_build`, `save_build`, `screenshot_build`, `share`) use `Once per event` counting, and UI interactions (`platform`, `language`, `focus_mode`, `app_update`, `optimization_alert`, `outbound_link`, `share_link`, `error_recovery`) leverage GA4's built-in `select_content` dimensions (`content_type` and `item_id`). Granular workspace context (`forced`, `active_tech_count`, `is_custom_grid`, `is_custom_modules`, `module_count`, `solve_type`) continues to flow into BigQuery `UNNEST(event_params)`.
5. **Standard `exception` Event Without Stack Traces & Production-Gated Static Error Pages**: Client error boundaries, dialogs, and static [`public/500.html`](../../public/500.html) emit GA4's standard `action: "exception"` event with `description` and `fatal` fields instead of dynamic `error.name` event names, leaving stack traces strictly to Sentry per [ADR-0002](./0002-deferred-error-monitoring-without-router-tracing.md). Both [`public/404.html`](../../public/404.html) (`not_found`) and [`public/500.html`](../../public/500.html) (`exception` and `hard_reset_500` recovery) gate `gtag.js` injection to `nms-optimizer.app` and non-bot/non-webdriver user agents.
6. **Variable-Supercharged Scope in `UserStatsDialog`**: [`UserStatsDialog`](../../src/components/AppDialog/UserStats/UserStatsDialog.tsx) charts only Platform Types with variable supercharged slot layouts (Starship, Multi-Tool, and Corvette), excluding fixed-supercharged platforms governed by **Recommended Builds**.
7. **Route-Scoped `page_view` Deduplication, Pre-Sanitization Acquisition Extraction, and BigQuery Referrer Reporting**: [`pageView.ts`](../../src/utils/analytics/pageView.ts) keys route `page_view` emission in [`Seo.tsx`](../../src/components/Seo/Seo.tsx) to `${lang}:${cleanPath}` (so initial `?platform=` normalization and platform selector switches do not fire duplicate `page_view` events or overwrite `document.referrer` with self-referrers), preserves all virtual modal/error screen `page_view` events under `category: "engagement"`, and captures inbound `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, and `ref` query parameters in [`useUrlSync.tsx`](../../src/hooks/useUrlSync/useUrlSync.tsx) before URL query sanitization. Combined client and server external referrers, full-path/app-intent referrers (`android-app://com.reddit.frontpage/`), campaign tags, and inbound **Shared Grid** (`?grid=`) loads are queried from bounded daily + current-day intraday BigQuery tables via [`scripts/report-referrers.py`](../../scripts/report-referrers.py) (`bun run perf:referrers`).
