# GA4, Measurement Protocol, and BigQuery Telemetry Contract

## Context

`nms_optimizer-web` dispatches analytics events through two transports: client-side `gtag` (`react-ga4`) when unblocked, and a server-side Measurement Protocol relay (`/api/events` in `nms_optimizer-service`) when ad blockers or DNS sinkholes block Google Analytics scripts. Downstream, two public Routed Dialogs—[`UserStatsDialog`](../../src/components/AppDialog/UserStats/UserStatsDialog.tsx) (`/userstats/`, backed by `/analytics/popular_data`) and [`PerformanceDialog`](../../src/components/AppDialog/Performance/PerformanceDialog.tsx) (`/performance/`, backed by `/analytics/performance_data`)—query the GA4 BigQuery Export dataset (`events_*` and `events_intraday_*`) as their primary data source, with the GA4 Data API (`BetaAnalyticsDataClient`) as a fallback.

Several subtle cross-system invariants govern how GA4, Measurement Protocol, and BigQuery serialize and aggregate event parameters:

1. **Boolean Parameter Serialization Divergence**: Client-side `gtag` serializes boolean parameters (`true` / `false`) as URL query strings, which BigQuery stores in `event_params.value.string_value` (`"true"` / `"false"`). In contrast, the GA4 Measurement Protocol JSON API converts JSON booleans (`true` / `false`) into `event_params.value.int_value` (`1` / `0`), leaving `string_value` as `NULL`.
2. **Web Vitals Delta Deduplication in BigQuery**: `/analytics/performance_data` deduplicates multi-table Web Vitals rows per `user_pseudo_id` by matching `COALESCE(metric_id, label)` against `^v\d+-\d+-\d+$` and summing `value`. Overwriting `label` with a DOM selector or non-ID string breaks delta deduplication.
3. **GA4 Custom Dimension Quota vs. Raw BigQuery Export**: BigQuery Export captures every key in `event_params` automatically without console registration, whereas the GA4 UI and `BetaAnalyticsDataClient` require explicit Custom Dimension / Custom Metric registration (subject to GA4 property limits).
4. **Fixed-Supercharged Recommended Builds vs. Organic Solver Telemetry**: Platform Types with fixed supercharged slot layouts (`superchargedFixed: true`, such as Exosuit and Exocraft) provide static curated **Recommended Builds**, so charting their supercharged technology popularity in `/userstats/` reflects preset layouts rather than organic solver variance.
5. **Cross-Origin Referrer Policy, Server-Relayed Attribution, and URL Query Sanitization**: Modern browsers default to `Referrer-Policy: strict-origin-when-cross-origin`, truncating external `document.referrer` values to origin-only (`https://www.reddit.com/`), while GA4's Measurement Protocol (`/api/events`) does not populate GA4's session-level `traffic_source` dimensions from `page_referrer` (leaving ad-blocked sessions marked as `(direct) / (none)` even though `event_params.page_referrer` in BigQuery preserves the true external origin). Furthermore, [`useUrlSync.tsx`](../../src/hooks/useUrlSync/useUrlSync.tsx) strips non-`platform`/`grid` query parameters and normalizes `/?platform=` on initial mount, which previously fired a duplicate `page_view` in [`Seo.tsx`](../../src/components/Seo/Seo.tsx) that overwrote the external `page_referrer` with a self-referrer and stripped inbound `utm_*` / `ref` parameters before async `gtag.js` initialization.

## Decision

1. **String-Normalized Boolean Event Parameters**: All boolean flags in [`GA4Event`](../../src/types/analytics.ts) (such as `supercharged`, `forced`, `is_custom_grid`, `is_custom_modules`, and `fatal`) are normalized to `"true"` or `"false"` strings before dispatch in [`tracking.ts`](../../src/utils/analytics/tracking.ts) so client `gtag` and server `/api/events` write identical `string_value` columns in BigQuery and GA4. On the read side, `/analytics/popular_data` coalesces `value.string_value` with `IF(value.int_value = 1, 'true', IF(value.int_value = 0, 'false', NULL))` to preserve historical server-relayed events.
2. **Web Vitals Attribution via `interaction_target` & `load_state`**: [`tracking.ts`](../../src/utils/analytics/tracking.ts) registers Core Web Vitals observers before awaiting the 3-second ad-blocker probe timeout, preserves `label: metric.id` (`^v\d+-\d+-\d+$`) for BigQuery deduplication, reuses the registered `customEvent:interaction_target` and `customEvent:load_state` dimensions to carry attribution selectors and load states across `INP`, `LCP`, and `CLS`, and omits the unused `TBT` observer.
3. **Minimal GA4 Custom Definitions + Rich BigQuery Context**: High-level reporting dimensions (`platform`, `tech`, `supercharged`, `solve_method`, `bonus_status`, `method`, `metric_name`, `interaction_target`, `interaction_type`, `load_state`, `app_version`, `tracking_source`) and metrics (`value`, `solve_duration_ms`, `input_delay`, `processing_duration`, `presentation_delay`) are registered in GA4, while granular workspace context (`forced`, `active_tech_count`, `is_custom_grid`, `is_custom_modules`, `module_count`, `solve_type`, `reason`) is queried via BigQuery `UNNEST(event_params)`.
4. **Standard `exception` Event Without Stack Traces**: Client error boundaries and dialogs emit GA4's standard `action: "exception"` event with built-in `description` and `fatal` fields instead of dynamic `error.name` event names, leaving stack traces strictly to Sentry per [ADR-0002](./0002-deferred-error-monitoring-without-router-tracing.md).
5. **Variable-Supercharged Scope in `UserStatsDialog`**: [`UserStatsDialog`](../../src/components/AppDialog/UserStats/UserStatsDialog.tsx) charts only Platform Types with variable supercharged slot layouts (Starship, Multi-Tool, and Corvette), excluding fixed-supercharged platforms governed by **Recommended Builds**.
6. **Route-Scoped `page_view` Deduplication, Pre-Sanitization Acquisition Extraction, and BigQuery Referrer Reporting**: [`pageView.ts`](../../src/utils/analytics/pageView.ts) keys route `page_view` emission in [`Seo.tsx`](../../src/components/Seo/Seo.tsx) to `${lang}:${cleanPath}` (so initial `?platform=` normalization and platform selector switches do not fire duplicate `page_view` events or overwrite `document.referrer` with self-referrers), standardizes virtual modal/error screen `page_view` events under `category: "engagement"`, and captures inbound `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, and `ref` query parameters in [`useUrlSync.tsx`](../../src/hooks/useUrlSync/useUrlSync.tsx) before URL query sanitization. Combined client and server external referrers, full-path/app-intent referrers (`android-app://com.reddit.frontpage/`), campaign tags, and inbound **Shared Grid** (`?grid=`) loads are queried directly from BigQuery via [`scripts/report-referrers.py`](../../scripts/report-referrers.py) (`bun run perf:referrers`).
