# Post-Paint Frame Yielding for Zustand Mutations and Zero-CLS Dialogs

## Context

`nms_optimizer-web` stores workspace state (grid layout, **Module Selection**, dialog visibility, **Platform Type**, and solve status) in Zustand stores backed by React's `useSyncExternalStore`. Wrapping a Zustand `set()` mutation inside `React.startTransition` does not defer rendering: `useSyncExternalStore` forces React 19 to bail out of concurrent transition lanes and commit the full subscriber tree synchronously inside the input event handler before the browser can paint. On mid-tier Android Chrome devices (the cohort measured by Google Search Console's CrUX Mobile report), synchronous commits during **Module Selection Dialog** open/close, **Session Reset**, **Technology Reset**, and **Platform Type** switches pushed `p75` Interaction to Next Paint (INP) above `200ms`. Meanwhile, an earlier attempt (`#770`, reverted in `553d6065`) to defer **Module Selection Dialog** content behind a short skeleton placeholder caused severe Cumulative Layout Shift (CLS) when the centered modal expanded to fit its dynamic module list, and sequential microtask execution in `LifecycleCoordinator` (`flushDeferredTasks()`) caused post-boot input delay on early header taps.

## Decision

1. **Cancelable Post-Paint Macrotask Yielding (`scheduleAfterNextPaint`) Instead of `startTransition` for Zustand**: Heavy cross-store or modal-mounting Zustand mutations triggered by discrete user taps (**Module Selection Dialog** open, **Module Selection Dialog** **Optimize** and dirty **Cancel**/backdrop rollback, **Session Reset**, **Technology Reset**, and **Platform Type** selection) yield one frame (`requestAnimationFrame` followed by a macrotask) via a shared cancelable, latest-wins `scheduleAfterNextPaint` seam rather than `React.startTransition`. Frame 1 paints only the native tap feedback (or modal close) with no artificial button `disabled` flash or loading spinner; frame 2 commits the store mutation atomically.
2. **Zero-CLS, Zero-Layout-Change Atomic Dialog Mounts**: **Module Selection Dialog** and `AppDialog` preserve their exact existing Radix markup, `.rt-CheckboxGroupRoot` spacing, and dynamic scrollbar clearance (`pr-3` when overflowing, `pr-1` otherwise) with zero skeleton placeholder and zero CLS, relying on the frame-1 post-paint yield so the click interaction completes its next paint before the modal mounts atomically on frame 2.
3. **Batched Store Resets & Inter-Task Idle Slicing**: Multi-field store transitions (`sessionCoordinator.resetTechnology` and solve-start initialization) batch writes per store rather than firing sequential `set()` calls, **Session Reset** dispatches analytics via `sendDeferredEvent`, and `LifecycleCoordinator` yields back to the browser's input queue between deferred `IDLE` tasks while keeping explicit test `flushDeferredTasks()` calls deterministic.

## Considered Options

- **`React.startTransition` Around Zustand Actions**: _Rejected_: `useSyncExternalStore` updates opt out of concurrent transition scheduling and still block the click event's next paint synchronously.
- **Skeleton-Deferred Dialog Body (`#770`)**: Mount an empty modal shell first and swap in the module list on a second render. _Rejected_: Resizing a `translate(-50%, -50%)` centered modal shifts its bounding box vertically and causes severe CLS (`553d6065`).
- **Persistent Hidden Dialog DOM**: Keep **Module Selection Dialog** mounted offscreen when closed. _Rejected_: Retains idle portal/checkbox DOM nodes throughout the session when a 1-frame post-paint yield achieves `< 50ms` tap INP cleanly.
- **Post-Paint Macrotask Yield + Atomic Mount (Selected)**: Completes tap paint in frame 1 without visual flicker and mounts or resets the tree atomically in frame 2 with zero CLS and zero layout changes.
